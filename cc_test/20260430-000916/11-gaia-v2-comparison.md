## 二、准确率下降原因分析

### 2.1 上下文污染已消除

v2 中不再出现上一题答案残留的问题：
- v1 有 3 题（#14, #21, #42）输出前一道题的答案 → v2 完全消除
- 但这 3 题在 v2 中仍然答错（模型本身能力不足，不是答案残留）

### 2.2 模型非确定性

| 题目 | v1 结果 | v2 结果 | 说明 |
|------|---------|---------|------|
| #47 (Guava) | ✓ Guava | ✗ Pineapple | 模型读指令不仔细，非确定性导致 |
| #48 (Doctor Who) | ✓ 154s | ✓ 75s | 同样正确但更快 |

### 2.3 答案提取差异

v1 使用原始输出子串匹配，v2 新增 `extractAnswer()` 函数。部分 v1 正确的题目在 v2 中因提取逻辑不够准确而失败：

| 题目 | 期望答案 | v2 提取结果 | 问题 |
|------|---------|------------|------|
| #27 (逻辑等价) | (¬A → B) ↔ (A ∨ ¬B) | "not a tautology" | extractAnswer 取了最后一个 bold 而非第一个 |
| #46 (鳄鱼) | 6 | 79 | 模型理解错误（记录数 vs 物种数） |
| #22 (小丑鱼) | 34689 | "one record" | 提取了错误 bold 文本 |

**修复**: 已更新 `compareAnswers` 先检查原始输出子串匹配，再检查提取答案。已更新 `extractAnswer` 按长度升序选择候选答案（短答案更可能是直接答案）。

### 2.4 模型 Provider 错误影响

v2 中 minimax-highspeed 错误仍然存在：
- 8 次 HTTP 400 错误（与 v1 相同）
- 5 次 TypeError: fetch failed（比 v1 多 2 次）

### 2.5 v2 新增正确题目

| 题目 | v1 结果 | v2 结果 |
|------|---------|---------|
| #39 (植物学蔬菜) | ✗ 遗漏 fresh basil | ✓ 完整列表 |
| #41 (洋基 at bats) | ✗ 527 | ✓ 519 |

---

## 三、结论

1. **独立 Session 有效消除上下文污染**，但无法提升模型本身的推理能力
2. **v2 准确率低于 v1 的主因是答案提取逻辑不够准确**，而非 Agent 能力下降
3. **修复提取逻辑后预计 v3 准确率在 40-45% 区间**（v1 水平 + 无上下文污染的净效果）
4. **最大的准确率瓶颈仍然是 Provider 稳定性**（minimax-highspeed HTTP 400 占 16% 的题目）

---

## 四、后续优化优先级

1. **P0: 修复 Provider 稳定性** — 切换主模型或增加 fallback → 预期 +8-12%
2. **P0: 修复答案提取逻辑** — 已完成，重跑验证 → 预期 +6-8%
3. **P1: 文件附件支持** → 预期 +4-6%
4. **P1: 搜索增强** → 预期 +4-6%
